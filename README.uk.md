# verstak-agent

[English](README.md)

Бекенд для відмовостійкої автоматизації бізнес-процесів із MCP. Агент тріажу пропонує дію за запитом або завантаженим документом. Агент перевірки звіряє ідентифікатор, суму й валюту з джерелом і повертає непідтверджені поля на виправлення. Людина погоджує або відхиляє перевірену пропозицію. PostgreSQL зберігає стан запуску, результати перевірки, рішення, витрати моделі та чекпоінти LangGraph. Погоджена дія створює запис справи в тій самій базі.

## Запуск демо

Запустіть стек із кореня репозиторію на Linux або в Docker Desktop у режимі Linux-контейнерів. Потрібен Docker Compose v2.

```bash
git clone https://github.com/Galactic717/verstak-agent.git
cd verstak-agent
cp .env.example .env
docker compose up --build -d --wait
```

| Сервіс | Локальна адреса |
| --- | --- |
| Swagger UI | <http://127.0.0.1:8000/docs> |
| MCP Streamable HTTP | <http://127.0.0.1:8001/mcp> |

Конфігурація Compose використовує демонстраційні облікові дані й детерміновану класифікацію без ключа провайдера. Для цього профілю використовуйте синтетичні запити. Експорти n8n містять три сценарії для тріажу через вебхук і погодження, перенесення даних із Excel до Google Sheets та планового звіту про якість і витрати. Щоб виконати той самий процес на локальній Qwen3-4B через Ollama, додайте конфігурацію моделі. Під час першого запуску ваги моделі завантажаться в іменований том Docker.

```bash
docker compose -f docker-compose.yml -f compose.ollama.yml up --build -d
```

### Створення й погодження запуску

Для команд Bash потрібні `curl` та `jq`.

```bash
API=http://127.0.0.1:8000
TOKEN=$(curl -fsS "$API/oauth/token" \
  -d grant_type=client_credentials -d client_id=demo \
  -d client_secret=verstak-demo-secret | jq -r .access_token)
AUTH="Authorization: Bearer $TOKEN"
RUN=$(curl -fsS "$API/workflows/triage/runs" -H "$AUTH" \
  -H 'Content-Type: application/json' -H "Idempotency-Key: demo-$(date +%s)" \
  -d '{"text":"Review invoice INV-1042 for USD 120.00"}' | jq -r .id)

curl -fsS "$API/runs/$RUN" -H "$AUTH" | jq
```

Перевіряйте стан запуску до появи `waiting_approval`, перегляньте `triage` та `verification` і надішліть рішення. Повторна перевірка покаже `succeeded` або `rejected`.

```bash
curl -fsS "$API/approvals/$RUN" -H "$AUTH" \
  -H 'Content-Type: application/json' -d '{"approved":true}' | jq
curl -fsS "$API/runs/$RUN" -H "$AUTH" | jq
```

Передайте PDF, CSV, XLSX або звичайний текст у multipart-полі `file` запиту `POST /documents`. Використайте отриманий `id` як `document_id` під час створення запуску. `GET /knowledge/search?q=...` шукає індексовані фрагменти в межах організації автентифікованого клієнта. [Колекція Postman](docs/postman_collection.json)

### Підключення MCP-клієнта

Для Streamable HTTP вкажіть `http://127.0.0.1:8001/mcp` і передайте bearer-токен. Для stdio встановіть Python 3.12 та `uv`, а потім налаштуйте клієнт на виконання команди з кореня репозиторію.

```bash
VERSTAK_MCP_API_TOKEN="$TOKEN" uv run --locked verstak-mcp --transport stdio
```

Інструменти шукають у базі знань, читають стан запуску й подають ідемпотентні запити на тріаж. FastAPI перевіряє переданий токен на кожному виклику. Погодження має окремий дозвіл API.

## Як виконується процес

- Рядок запуску в PostgreSQL також зберігає стан постановки в чергу. Celery Beat запускає диспетчер, який резервує готові рядки й надсилає завдання в Redis. Після завершення строку резервування перерване завдання знову доступне для доставки.
- Рекомендаційне блокування PostgreSQL серіалізує обробку одного запуску. Граф зупиняється перед бізнес-дією і відновлюється в тому самому потоці чекпоінтів. Унікальний ключ дії захищає запис справи від повторного створення.
- Pydantic перевіряє пропозицію моделі. Воркер резервує кошти в цілих мільйонних частках долара перед кожним викликом. На один запуск припадає щонайбільше три спроби разом із виправленнями.
- Окремий вузол перевірки звіряє ідентифікатор і пару сума–валюта з текстом запиту або доданого документа. Він зберігає результат і повертає непідтверджені поля агенту тріажу в межах тих самих лімітів спроб і витрат.
- Пошук поєднує рейтинг BM25 у PostgreSQL та рейтинг pgvector HNSW. Детермінований векторизатор використовує лексичні ознаки для відтворюваності демо.

## Перевірка й оцінювання

```bash
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run mypy --strict src
uv run pytest tests/unit
docker compose exec -T api verstak-eval
```

Обидві моделі Qwen пройшли ті самі 30 синтетичних кейсів локально в Ollama з лімітом у чотири ядра CPU. Вбудовані правила слугують базовим варіантом. Затримку виміряно для одного виклику класифікації.

| Локальний провайдер | F1 вибору інструмента | Відповідність схемі | Точність витягнутих полів | Затримка p95 |
| --- | ---: | ---: | ---: | ---: |
| Вбудовані правила | 0,9333 | 100% | 96,67% | 0,0518 мс |
| Qwen3-1.7B Q4_K_M | 0,7586 | 93,33% | 46,67% | 8,60 с |
| Qwen3-4B Q4_K_M | 0,9153 | 96,67% | 96,67% | 14,23 с |

Витрати на API під час локальних прогонів склали $0. [Методика оцінювання й сирі звіти](evals/README.md)

Локально пройшли 78 Python-тестів із покриттям рядків 87,13%, два Playwright-сценарії й перевірка наскрізного трасування в Jaeger на Linux-стеку Compose. У всіх 10 тестах зі збоєм після запису дії відновлення завершилося одним записом на запуск. У 10 тестах із навмисно помилковими реквізитами пропозиції дійшли до погодження після одного виправлення вбудованим провайдером. Окрема перевірка з примусовою зупинкою воркера під час погодження підтвердила відновлення з одним викликом моделі й одним записом дії. GitHub Actions запускає інтеграційні тести, тести з ін’єкцією збоїв, Gherkin-сценарій, браузерні перевірки й перевірку трасування.
